A B2B logistics platform where shippers, carriers and forwarders run RFQs, bidding, deals and shared operations across road, sea, air and rail. Working with a product owner, I own the whole technical side as the only engineer: architecture, backend, web and iOS/Android apps, infrastructure and delivery.

It is a .NET 10 modular monolith of 13 domain modules (shipment requests, bids, deals, tracking, dock scheduling, documents and more), built with DDD, Clean Architecture and CQRS on MediatR. Domain events keep the modules consistent; architecture tests and ADRs keep the boundaries where they were drawn.

Multi-tenant security runs on Keycloak (OIDC, RBAC) with tenant isolation. Every uploaded document is scanned with ClamAV and read with Tesseract OCR. Real-time updates travel over SignalR with a Redis backplane. More than 3,000 automated tests (xUnit, Testcontainers PostgreSQL, NetArchTest) gate a Docker and GitHub Actions pipeline to Azure Container Apps. The web app is React (Vite); mobile is React Native (Expo).

APPLIED AI LAYER

AN LLM ASSISTANT THAT CALLS REAL TOOLS, WITH ITS COSTS ON THE BOOKS
MODEL APIAnthropic Messages API
LOOPServer-side tool use
ROUTINGSmall model for simple turns, larger for planning
LEDGERPer-tenant tokens & cost

The logistics platform ships with an AI assistant built on the Anthropic Messages API. It runs a server-side tool-use loop that calls live road-routing tools, so its answers about routes come from real data.

Cost is designed in from the start: model routing sends simple turns to a small model and planning to a larger one, prompt caching is tiered, and every call lands in per-tenant token and cost accounting that records counts, never tenant text.

Eight more LLM features run beside the assistant: cross-language chat translation, message assessment and action extraction, offer explanations, dashboard and workflow drafting, and web-search-grounded lane intelligence.
